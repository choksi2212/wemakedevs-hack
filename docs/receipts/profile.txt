# GRAPH.PROFILE — live receipt (falkordb 6.0.0, sever_demo tenant, regenerated 2026-10-15)

Query (canonical attack-path lookup, hero -> Domain Admins, 12-hop traversal
pattern over the abusable-relationship vocabulary):

    MATCH (o {objectid: $oid}), (t {objectid: $target})
    WITH shortestPath((o)-[:MEMBER_OF|GENERIC_ALL|...|AZKVContributor*..12]->(t)) AS p
    RETURN p

GRAPH.PROFILE binds parameters through the CYPHER params header (the same
transport GRAPH.QUERY uses); the earlier "PROFILE does not bind parameters"
note was wrong — params-bound PROFILE is the transport below, measured live
via sever.core.falkor_port.FalkorGraphPort.profile().

## Honest read

The 6.0.0 planner resolves `objectid` range indexes only when the label is
bound in the pattern. Load-bearing SEVER queries match by objectid alone
(owned principals and crown jewels carry several possible labels), so they
take the All Node Scan path: ~4-8ms of scan per 1480-node tenant — flat and
sub-10ms per query at every wall size we measured (444K nodes / 3.73M edges,
median 3.66ms — see scale_wall.json). Label-bound lookups are 2-3 orders
faster via Node By Index Scan; binding labels into the hot templates is a
known future optimization, deliberately not smuggled in mid-event.
