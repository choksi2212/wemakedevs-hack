# SEVER

**Attack-path tools stop at advice. SEVER closes the loop: ranked cut → human gate →
live re-query → before/after receipts — per-tenant, in milliseconds.**

An on-call identity-security agent on [FalkorDB](https://falkordb.com): it ingests
BloodHound-style Active Directory + Entra identity graphs, reacts to a live
findings stream, walks the real exploitable paths to Domain Admin, ranks the one
edge whose removal kills the most paths, and — only after an explicit human
approval — severs it and proves the attack surface actually collapsed.

Built at **Graph Hacks** (WeMakeDevs × FalkorDB), Oct 15–18 2026.

## Reproduce everything

```bash
git clone -b develop https://github.com/choksi2212/wemakedevs-hack   # main holds only the stub README
cd wemakedevs-hack                                                       # until final submission
docker compose up -d                       # FalkorDB 6.0.0 + browser UI at :3000
mkdir -p data/ad_sample && cd data && curl -sLO \
  https://raw.githubusercontent.com/SpecterOps/BloodHound-Docs/main/docs/assets/sample-data/ad_sampledata.zip \
  && mkdir -p entra_sample && curl -sLO \
  https://raw.githubusercontent.com/SpecterOps/BloodHound-Docs/main/docs/assets/sample-data/entra_sampledata.zip \
  && unzip -o ad_sampledata.zip -d ad_sample && unzip -o entra_sampledata.zip -d entra_sample && cd ..
pip install -e ".[dev,console,memory,agent]"  # openai ([agent]) is imported by tests/test_agent.py;
                                              # the console itself never needs it
python -m pytest                           # DB-free units run anywhere; engine tests need docker, skip cleanly
                                           # Windows note: no `unzip` — `tar -xf <zip> -C <dir>` reads the same zips
python -m pytest tests/test_live.py        # live-engine regression (docker compose up -d)
python scripts/rehearse.py                  # beat 1  (hero interdiction)
python scripts/case_memory_live.py start  --thread case-T2-live --graph sever_t2
python scripts/case_memory_live.py resume  --thread case-T2-live --graph sever_t2   # beat 2 (fresh process!)
python scripts/hybrid_live.py                                   # beat 3  (cross-world)
python scripts/scale_wall.py --tenants 300                      # beat 4  (scale wall)
python -m sever.eval.ablation                                  # ablation receipt (5/5 vs 0/5)
```

Sample data lands in `data/ad_sample` + `data/entra_sample` (both Apache-2.0
SpecterOps sample zips; see Disclosures) — the same defaults every script and
test uses, overridable via `SEVER_SAMPLE_DIR` / `SEVER_ENTRA_FILE`.

There is exactly one engine. Every beat above is the real FalkorDB Cypher from
`sever/core/falkor_port.py` — no in-memory double exists anywhere (rule 3 by
construction: remove FalkorDB and SEVER does not run). Only the DB-free units —
ETL parsing against the real sample, tenant generation, findings schema,
human-gate and LLM-seam semantics — execute without the engine.

## Deployment

**Live deployment**: **https://sever-console.onrender.com** — the console
(FastAPI) on Render's Singapore free tier, connected to a **FalkorDB Cloud**
free-tier instance (`ap-south-1`, the engine's own managed cloud). The demo
estate auto-loads at boot; the live receipts for the same substrate are in
[`docs/receipts/receipts_cloud_live.json`](docs/receipts/receipts_cloud_live.json)
(hero arc on the Cloud: 1,480 nodes / 12,450 edges loaded in 16.8s, breach 0→1,
two human-gated cuts, COLLAPSED). Self-deploy either layer from this repo:

- **Everything self-hosted (shipped)**: `docker compose up -d` — FalkorDB 6.0.0
  on :6379 (browser UI on :3000), persisted in `./out/falkordb-data`, restarted
  automatically on reboot (`restart: unless-stopped`). Any self-hosted or remote
  FalkorDB works by pointing `SEVER_FALKOR_HOST/PORT` at it (`.env.example`);
  FalkorDB Cloud equally — set `SEVER_FALKOR_USER/PASSWORD` (nothing in the
  client is docker-specific).
- **Console anywhere Docker runs**: `docker build -t sever-console . && docker
  run -p 8000:8000 --env SEVER_FALKOR_HOST=... --env SEVER_FALKOR_PORT=...
  --env SEVER_FALKOR_USER=... --env SEVER_FALKOR_PASSWORD=... sever-console` —
  or one-click the `render.yaml` blueprint (Render → New → Blueprint → this
  repo; secrets stay `sync: false` so credentials never touch the repo).
- **Console without Docker**: `uvicorn sever.console.app:app --host 0.0.0.0
  --port 8000`.
- Optional tuning (only for long cross-domain tie-set analysis): uncomment the
  `FALKORDB_ARGS` block in `docker-compose.yml` (`TIMEOUT_DEFAULT 0`) — the
  client already passes explicit per-query timeouts.
- **Free-tier reality (verified live on the deployment above)**: Render's
  free plan spins a web service down after ~15 min without traffic; the next
  request then pays a ~30–60s cold start. The live console stays warm with a
  10-minute keepalive ping (`curl -s -m 30 https://sever-console.onrender.com/api/state`
  from a Task Scheduler job / cron) — reuse that for your own deploy if you
  want zero cold starts.
- **Boot semantics (verified live)**: the console connects to FalkorDB at
  import time and is fail-fast — an unreachable engine exits the process
  with `ConnectionError` rather than serving a broken UI; an **empty** graph
  auto-loads the sample estate in one boot (4.3s self-hosted / 16.8s on
  Cloud); an **existing** graph boots without reloading (~0.9s). A vanished
  demo graph therefore self-heals on the next deploy.

## How it works

```
BloodHound CE + AzureHound collectors ──▶ ETL (two-pass, BloodHound-faithful)
        │                                       │  1,480 nodes / 12,450 edges / 0 dangling
        ▼                                       ▼
 findings stream ──▶ SEVER agent ──▶ FalkorDB (graph-per-tenant)
 (breach-timeline        │  paths, scoring, proposals        │
  replay, live-mutating) ▼                                   ▼
                   HUMAN GATE ──▶ cut ──▶ re-query ──▶ receipts (JSON, ms)
```

- **FalkorDB is load-bearing** (rule 3): every path query, score, cut and
  re-verification is FalkorDB Cypher — `sever/core/falkor_port.py` holds the
  exact queries as module constants, live-verified forms in
  [`docs/CYPHER.md`](docs/CYPHER.md) (including the engine quirks we mapped:
  shortestPath as a WITH-expression, `*..N` bounds, SPpaths' raw node ids).
- **Graph data model**: [`docs/GRAPH_MODEL.md`](docs/GRAPH_MODEL.md).
- **Human gate**: `approve_and_cut()` passes *only* on the exact value `True` —
  no caller can slip a truthy value through; the console gate is an HTTP 403
  without it. The LLM narrates; Cypher works; a human decides. (SpecterOps
  keeps its own agentic tooling read-only for the same reason.)
- **LLM seam**: any OpenAI-compatible endpoint via env config, offline
  `NullLLM` fallback — the product never depends on a model to function.
- **Case memory**: investigations are resumable LangGraph flows checkpointed
  by `FalkorDBSaver` — state lives in the graph DB, shared across processes
  and agents (Track 2's "agents that remember across sessions and share state";
  full key-focus mapping in [`docs/T2_MEMORY.md`](docs/T2_MEMORY.md)).
- **Eval ablation**: the same estate questions answered by graph traversal
  (5/5) vs keyword-only retrieval (0/5) — the rule-3 proof, quantified:
  [`docs/receipts/ablation.json`](docs/receipts/ablation.json).

## Tests

**DB-free units (run anywhere)**: ETL parsing fidelity vs the real sample —
1,480 nodes / 12,450 edges, zero dangling — Entra overlay parsing and bridge
derivation, synthetic tenant generation, findings-stream schema + ATT&CK
narration, Cypher-injection guards, human-gate and LLM-seam semantics.
**Engine tests (live FalkorDB via `docker compose up -d`; skip cleanly when
it's down)**: graph-port semantics and load counts vs the ETL, the agent
interdiction loop, console API, case memory, the ablation, and the live
cascade regression — gated cut rounds until reachability collapses.

## Disclosures

- **Simulated environment**: estates are built from the official SpecterOps
  BloodHound CE + AzureHound sample data (Apache-2.0, credited in-repo);
  findings are a labeled deterministic breach-timeline replay. No real
  organization's data. Per-tenant identities are synthetic injective remaps.
- **AI-assisted development** (rule 11): this project was built with AI
  assistance under human direction — architecture decisions, graph model,
  traversal semantics, acceptance criteria and every merge were reviewed by
  the author, who can defend each component. Commit history is fully in-window.
- **Tracks**: Agents That Act on Connected Data (primary) · Agent Memory and
  Coordination (case memory via FalkorDBSaver).
