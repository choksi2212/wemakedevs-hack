# SEVER

**Attack-path tools stop at advice. SEVER closes the loop: ranked cut → human gate →
live re-query → before/after receipts — per-tenant, in milliseconds.**

An on-call identity-security agent on [FalkorDB](https://falkordb.com): it ingests
BloodHound-style Active Directory + Entra identity graphs, reacts to a live
findings stream, walks the real exploitable paths to Domain Admin, ranks the one
edge whose removal kills the most paths, and — only after an explicit human
approval — severs it and proves the attack surface actually collapsed.

Built at **Graph Hacks** (WeMakeDevs × FalkorDB), Oct 15–18 2026.

> **Branch map:** development happens on `feat/*` branches merged into `develop`
> (always green). `main` holds a stub README until final submission. Track
> `develop` for the real thing.

Every beat works fully offline against the in-memory mock engine too —
`python scripts/rehearse.py` with no docker — because both engines implement
the same `GraphPort`, and the live tests assert the parity.

## How it works

```
BloodHound CE + AzureHound collectors ──▶ ETL (two-pass, BloodHound-faithful)
        │                                       │  1,480 nodes / 12,450 edges / 0 dangling
        ▼                                       ▼
 findings stream ──▶ SEVER agent ──▶ FalkorDB (graph-per-tenant)
 (breach-timeline        │  paths, scoring, proposals        │
  replay, live-mutating) ▼                                   ▼
                   HUMAN GATE ──▶ cut ──▶ re-query ──▶ receipts (JSON, ms)
```

- **FalkorDB is load-bearing** (rule 3): every path query, score, cut and
  re-verification is FalkorDB Cypher — `sever/core/falkor_port.py` holds the
  exact queries as module constants, live-verified forms in
  [`docs/CYPHER.md`](docs/CYPHER.md) (including the engine quirks we mapped:
  shortestPath as a WITH-expression, `*..N` bounds, SPpaths' raw node ids).
- **Graph data model**: [`docs/GRAPH_MODEL.md`](docs/GRAPH_MODEL.md).
- **Human gate**: `approve_and_cut()` passes *only* on the exact value `True` —
  no caller can slip a truthy value through; the console gate is an HTTP 403
  without it. The LLM narrates; Cypher works; a human decides. (SpecterOps
  keeps its own agentic tooling read-only for the same reason.)
- **LLM seam**: any OpenAI-compatible endpoint via env config, offline
  `NullLLM` fallback — the product never depends on a model to function.
- **Case memory**: investigations are resumable LangGraph flows checkpointed
  by `FalkorDBSaver` — state lives in the graph DB, shared across processes
  and agents (Track 2's "agents that remember across sessions and share state";
  full key-focus mapping in [`docs/T2_MEMORY.md`](docs/T2_MEMORY.md)).
- **Eval ablation**: the same estate questions answered by graph traversal
  (5/5) vs keyword-only retrieval (0/5) — the rule-3 proof, quantified:
  [`docs/receipts/ablation.json`](docs/receipts/ablation.json).

## Disclosures

- **Simulated environment**: estates are built from the official SpecterOps
  BloodHound CE + AzureHound sample data (Apache-2.0, credited in-repo);
  findings are a labeled deterministic breach-timeline replay. No real
  organization's data. Per-tenant identities are synthetic injective remaps.
- **AI-assisted development** (rule 11): this project was built with AI
  assistance under human direction — architecture decisions, graph model,
  traversal semantics, acceptance criteria and every merge were reviewed by
  the author, who can defend each component. Commit history is fully in-window.
- **Tracks**: Agents That Act on Connected Data (primary) · Agent Memory and
  Coordination (case memory via FalkorDBSaver).
